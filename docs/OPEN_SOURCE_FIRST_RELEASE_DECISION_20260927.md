# First-release disposition: bounded SDK + ARA, no ecosystem-wide rights hold

**Decision date:** 2026-09-27. **Canonical existing goal:** `ECOSYSTEM-OPEN-SOURCE-STRATEGY-001`; **COSV:** `20010010100000`. **Classification:** source-evidence release *scope* decision, **not** copyright-holder consent, license amendment, production authorization, tag, artifact publication, or runtime receipt. Canonical Registry generation 265 was read before opening this decision branch; task remains ACTIVE/CHECKED_OUT and release_authorized=false.

## Executive release-scope decision

**First-wave target:** the existing independently reusable **ARA dependency-free baseline** and the **StegVerse SDK base distribution** *only*. Stage ARA first because its release manifest declares no required runtime dependencies, then stage the SDK **base package only** after exact built-package review. Do not condition these base-only candidates on making the optional `governed-test` dependency chain redistributable. Preserve all existing repository grants; this scope choice neither rescinds nor expands them.

This is a **candidate selection**, not an authorized new public tag or release. ARA's declared `public_review` gate is distinct from `stable_release_authorized`. The SDK's existing source MIT grant is not a grant for its separately pinned Git extras, vendored content or any external generated wiki material.

**Important rights distinction:** Existing correctly scoped MIT-licensed material may continue to be used under the applicable existing grant, with copyright and permission notices retained. This audit cannot certify the legal chain for *every file* in an entire repository or confer any new release authority. Public visibility and a GitHub license badge are insufficient for claims about separately authored files, imported materials, optional dependencies, or official production service access.

## Exact evidence required to turn the two candidate rows into an allowed release

1. **Freeze exactly one ARA candidate and one SDK base candidate** by full Git SHA; obtain a complete source-to-distribution file manifest, build reproducibility evidence, exclusion list for generated/private material, and compare wheel/sdist or static-site contents to approved source. Do not advance an unrelated 1.4/1.5 branch under an SDK 1.3 release tag.
2. **Clear rights at those exact manifests:** identify each material file's origin, reachable author/coauthor contributions, external imports, existing licenses and required notices; obtain verifiable actual-holder consent or a demonstrated applicable existing grant for each uncertain contribution. Keep sensitive instruments restricted and publish only their decision refs.
3. **Build a frozen consumer SBOM and test the selected distribution.** ARA dependency-free default should validate without optional `jsonschema`; SDK base should verify resolved direct/transitive distributions and notices on Python >=3.9. Test any optional Python >=3.11 extras separately without bundling them into the first-wave source distribution.
4. **Verify public packaging safety:** sensitive-data/key scanning, no unauthorized private repositories, no external generated DeepWiki prose/diagrams, no nonpublic material in artifact paths; distinguish public protocol conformance from official InTr, WorkerCoordinator or Master Records authority.
5. **Obtain actual repository-owner publication decision and relevant rights/patent/trademark counsel review,** with immutable evidence references and current exact-head checks. An ordinary source-audit PR merge is not this approval.
6. **Publish and read back independently, only after ALLOW:** use each source repository's own approved workflow and record tag/artifact hash; for ARA distinguish `public_review` from separately authorized stable; for SDK independently verify the actual release package and any public wiki tag-to-source mapping. A release requiring governed publication must also carry the original applicable transition and Master Records evidence; GitHub CI is not a substitute.

**First actionable failure at present:** `DENY:RELEASE_SCOPE_RIGHTS_UNVERIFIED` for both exact new release artifacts: contributor/import/file-level rights and immutable distribution manifests are not yet cleared. For Core-Lite separately: `DENY:SOURCE_LICENSE_SCOPE_UNVERIFIED` under its already-existing issue #34. No additional organization root-license census or replacement task can resolve these predicates.

## Native-owner execution and stop condition

- **ARA native owner:** freeze and independently validate its self-contained 0.2.0 candidate first; no claim that the declared `ALLOW/public_review` means new stable-release authorization.
- **SDK native owner:** freeze one *base-only* exact candidate on the intended version branch, build and enumerate real wheel/sdist contents, verify all three direct dependencies and their pinned resolved transitives; explicitly qualify extras.
- **Core-Lite native owner:** maintain issue #34's rights investigation independently of the baseline release; its absence from wave one is an intentional exclusion rather than a permanent rights finding.
- **Central existing goal:** track only candidate proof and resulting authorization/denial, not 252 repeat root-license searches. Preserve `ACTIVE/CHECKED_OUT` and COSV until the published, provenance-backed first release and all actually required goal predicates have been independently validated. Treat future additional components as separate scoped waves under their current native owners, not an implicit requirement that the entire known universe be relicensed.
