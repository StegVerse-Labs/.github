## DeepWiki steering: configuration caution

There is **no** `.devin/wiki.json` on SDK `main` at this verification. Cognition's current [official configuration documentation](https://docs.devin.ai/work-with-devin/deepwiki) requires **both** `repo_notes` and a nonempty `pages` array. When the file is present, **only** specified pages are generated (limit 30 pages for standard accounts). A `repo_notes`-only configuration proposed earlier in conversation is no longer valid against that documentation. Do **not** commit or merge a speculative page list that could silently replace the existing broader DeepWiki index.

Before introducing the configuration, obtain the **complete current page tree** using official [public read-only DeepWiki MCP](https://github.com/CognitionAI/deepwiki) `read_wiki_structure` (no Devin installation required), reconcile every page against the 30-page limit and decide what to preserve. Generated pages can be read with `read_wiki_contents` for review, but the current ChatGPT environment has no DeepWiki MCP connector and direct HTTP retrieval from the execution container failed DNS resolution on 2026-09-25. Therefore **complete DeepWiki text and exact full page inventory have not been imported or verified** by this pilot. Owner screenshots establish only the visible pages.

## Safe integration into the existing official SDK wiki

1. Retain the existing `sdk.stegverse.org` builder, tests, exact-source manifest, PR validation and main-only Pages deployment unchanged until a reviewed enhancement is available.
2. Acquire complete DeepWiki structure + content using an authorized read-only exporter, recording source repository, indexing revision, retrieval time, page paths, SHA-256 and source-code links. Do not grant Devin GitHub write access, use a second device or require another production runtime.
3. Stage external generated Markdown under `docs/deepwiki-review/` on a nondefault SDK branch. Validate completeness, links, source citations and third-party documentation reuse conditions; compare against exact SDK source and flag synthesized claims as generated, not runtime evidence.
4. Extend the **existing** SDK Pages builder to include reviewed Markdown and an explicit index, preserving the six existing exact canonical sources and failing closed on missing pages or mismatched provenance. Add targeted tests and expand `wiki-source-manifest.json` for reviewed imported page SHA-256 values and source revision.
5. Use the existing SDK wiki owner history and applicable current publication/propagation owners for source-only PR review and any approved Pages mutation; use existing InTr/Master Records proof for governed publication where required. Do not reopen retired owner or create duplicate wiki. The historical deployment and current code are separate from new deployment observation.
