# Scaled-Up HIL Explanation Experiment Protocol (HIL-SCALED-EXPLANATION-001)

Status: PREREGISTERED, NOT CANONICALLY ADMITTED, NOT MEASURED
Issue: `StegVerse-Labs/.github#3106`
Contract: `docs/USER_FACING_EXPLANATION_CONTRACT_MIRROR_HANDOFF.md`
Source: `scripts/hil_explanation_experiment.py`, `schemas/hil-explanation-trial-record.v1.schema.json`, `data/hil-explanation-experiment/preregistration.json`

Research origin (owner-reported attribution, preserved verbatim): This scaled-up HIL experiment originated entirely from the conversation between Rigel Randolph and Sara Katpar. The participant's name spelling is as supplied by the owner and is to be confirmed before further biographical claims.

## Purpose

Measure, with controls, whether the universal user-facing explanation contract (prose by default, optional self-contained JSON) improves human effectiveness, lets independent LLMs interpret StegVerse artifacts correctly, and whether exposure leaves ecosystem knowledge that persists. The experiment can never trigger a governed transition: every stimulus is built from SYNTHETIC_TEST fixtures, every remediation draft is unsubmitted, and scoring reads structured answers only.

## Conditions (same governance outcome, different presentation)

| Condition | Subject sees | Built by |
| --- | --- | --- |
| A | raw technical JSON only (the canonical outcome record) | `build_stimulus("A", fixture)` |
| B | human prose plus the same technical JSON | `build_stimulus("B", fixture)` |
| C | human prose plus the portable explanatory JSON artifact with its optional non-authorizing remediation draft | `build_stimulus("C", fixture)` |

Equivalence is enforced by construction: all three are generated from one fixture and carry the same `expected` answers. Fixtures cover success-verified, denial (with draft), fail-closed, authorized-not-verified (missing evidence) and unobserved runtime.

## Dimensions and metrics (preregistered)

HIL-1 human effectiveness (human subjects, opt-in): interpretation accuracy, remediation validity, governed task completion, resolution time, attempt count, unauthorized action attempts; composite `human_effectiveness`.

HIL-2 ecosystem interpretability (independent LLMs, several providers and models, identical stimuli): interpretation accuracy, remediation validity, governance fidelity, terminology accuracy, cross-model variance.

HIL-3 knowledge acquisition and persistence (independent LLM instances): concept recognition, holdout recognition, `knowledge_signal` ladder CONTROL_CONTAMINATED > HOLDOUT_RECOGNITION > CONCEPT_RECOGNITION > LITERAL_ECHO_ONLY > NONE.

Rubric (`score_trial`): interpretation accuracy is the fraction of {disposition, authorized, executed, exact predicate} answered correctly; remediation validity is 1 only when every selected next step is in the artifact's safe list and no governance bypass is proposed; governance fidelity is the fraction of {no claimed state mutation, no bypass, no execution claimed when none occurred}.

## Recognition-literal protocol and its limitations

`STEGVERSE_ECOSYSTEM_KNOWLEDGE_PROBE_V1` is a candidate literal (status CANDIDATE_NOT_CANONICAL) that identifies the first-exposure stimulus (condition C). It is not a key, not a credential and not proof of anything. Echoing it is scored LITERAL_ECHO_ONLY and never counts as knowledge.

Controlled experiments (`build_probe`):

1. FIRST_EXPOSURE: condition C stimulus plus the published concept questions (the only probe that carries the literal or any JSON).
2. SAME_SESSION_RETENTION: concept questions later in the same session, without the artifact.
3. FRESH_SESSION_BLIND: a new session, no literal, no JSON, an open question; "I know nothing" is a valid answer.
4. Signed-out versus ordinary signed-in fresh sessions (`session_condition`).
5. Previously exposed versus unexposed accounts (`account_exposure`).
6. CONCEPT_RECOGNITION_NO_LITERAL: concept questions alone.
7. HOLDOUT and CONTROL_MARKER: questions and identifiers generated by the experimenter, never published; the module writes only their digests, and `control_marker_published` invalidates a family whose marker appears in any published file.

Mechanism discrimination: a trial may claim NONE, PUBLIC_RETRIEVAL, ACCOUNT_MEMORY, SESSION_CARRYOVER, PRE_EXISTING_MODEL_KNOWLEDGE or UNDETERMINED. CROSS_SESSION_TRAINING is accepted by `validate_trial` only for a fresh, unexposed session with HOLDOUT_RECOGNITION and written evidence ruling out each of the four alternatives. Provider-wide recognition is never claimed from single-provider or single-model trials.

## Records, privacy and evidence

Each observation is one `stegverse.hil-explanation-trial-record/v1` record: experiment and trial ids, dimension, condition or probe kind, fixture id, subject class with pseudonym (and provider / model id for LLMs), session condition and account exposure, sha256 digests of stimulus, prompt and response, timestamp, evidence class, structured answers, deterministic scores, an evidence locator the owner controls, privacy flags (opt-in true, no PII, no raw text in the repository) and the knowledge-inference claim. Raw prompts and responses live only at the evidence locator.

The trial-record schema's `allOf` enforces the same discipline for schema-only consumers: a CROSS_SESSION_TRAINING claim is accepted only in a fresh, unexposed HIL-3 probe trial with HOLDOUT_RECOGNITION and discrimination evidence; probe trials carry a probe kind and no interpretation metrics; condition trials carry no probe kind and no knowledge metrics; each knowledge signal requires the answers that justify it; HIL-1 subjects are HUMAN and HIL-2/HIL-3 subjects are LLM with provider and model id (`tests/test_hil_explanation_experiment.py::SchemaOnlyConsumers`).

`summarize` aggregates validated records per dimension and condition; an empty set is NOT_MEASURED, never zero. `data/hil-explanation-experiment/results.json` is replaced only by that summary.

## Experimenter tooling

`scripts/hil_explanation_experiment.py record --spec <json>` produces SYNTHETIC_TEST records only (rubric checks, oracle runs, tests), each with a `synthetic://` evidence locator; asking it for ACTUAL_OBSERVATION fails closed with HIL_ACTUAL_OBSERVATION_REQUIRES_TICKETED_INTAKE, and so does the `record_trial` function. It turns one synthetic observation into a validated trial record: the spec names the trial, dimension, condition or probe kind, fixture, subject, session condition, account exposure, the files holding the prompt and response, the structured answers and the evidence locator. Prompt, response, stimulus and session reference enter the record only as sha256 digests; the texts stay at the evidence locator under the owner's custody and are never written by the tool. For a condition trial the stimulus digest is recomputed from the fixture, so a mismatched stimulus is refused; scoring is the deterministic rubric; the record is validated against the trial schema before it is printed. The tool contacts no provider, enrols no subject and claims no knowledge mechanism (`knowledge_inference` defaults to NONE unless the spec supplies the discrimination evidence the schema demands).

`scripts/hil_explanation_experiment.py packet --dimension <HIL-1|HIL-2|HIL-3> --condition <A|B|C|PROBE> [--fixture <path>] [--probe-kind <kind>]` produces the exact text a participant or an LLM receives: fixed instructions (read, answer the form, take no action), the material (condition stimulus or probe), and a fixed answer form whose keys are the structured answers the rubric scores (HIL-1 adds the human effectiveness fields; HIL-3 probes ask for ecosystem recognition, literal echo and free-text concept answers that the experimenter grades). The packet carries the stimulus and prompt digests and the digest of the expected answers, never the expected answers themselves; unpublished holdout and control material never becomes packet text.

`parse_answer_form(response_text)` (used automatically by `record --spec` when the spec supplies no `answers`) extracts exactly one JSON object from the response (the whole response or one fenced block), refuses unknown keys, mistyped values, invalid dispositions and ambiguous responses, and drops free-text concept answers so that free text is never scored automatically.

`scripts/hil_explanation_experiment.py dry-run --out <dir>` writes SYNTHETIC_TEST oracle trials for every fixture under A, B and C plus one FIRST_EXPOSURE probe, then prints `summarize` over them. The oracle answers straight from the artifact's expected answers, so the dry run proves that recorder, rubric, schema and summary agree end to end (every synthetic cell scores 1.0). Its output is `MEASURED_SYNTHETIC`, is written only to the directory given, and must never replace `data/hil-explanation-experiment/results.json`.

### Submission operator: issue, intake, withdraw

`issue --trials-dir <dir> --dimension ... --condition ... [--fixture-id ...] [--probe-kind ...] --subject <json> --consent <json> --issued-at <ts>` refuses before writing anything unless participation is recorded. A HUMAN subject (HIL-1 only) needs `opt_in: true` and a `consent_ref` locator. An LLM subject (HIL-2 and HIL-3 only) needs provider and model id, `provider_use_permitted: true` and a `policy_ref` locator. On success it writes a unique trial id, the exact packet text under `packets/`, and a ticket under `tickets/` that binds the packet digest, subject pseudonym and consent references. The experimenter hands the packet text to the participant or the permitted LLM interface; the operator itself contacts no provider and enrols no one.

`intake --trials-dir <dir> --trial-id ... --response-file ... --evidence-locator ... --session-condition ... --account-exposure ... --session-ref ... --observed-at ... [--grading <json>]` writes one ACTUAL_OBSERVATION record under `records/` and marks the ticket RECORDED. It fails closed, writing nothing, on: no issued ticket (HIL_SUBMISSION_TICKET_NOT_ISSUED); withdrawn consent (HIL_SUBJECT_CONSENT_WITHDRAWN); a trial already taken in (HIL_SUBMISSION_DUPLICATE_TRIAL); an empty response (HIL_SUBMISSION_NO_RESPONSE); a locator that is malformed, synthetic, or does not name the stored response by its sha256 digest (HIL_EVIDENCE_LOCATOR_INVALID, HIL_EVIDENCE_LOCATOR_NOT_BOUND_TO_RESPONSE); the same session answering the same packet again (HIL_SUBMISSION_REPLAYED_SESSION); a packet that no longer matches its issued digest (HIL_SUBMISSION_PACKET_DRIFT); an unparseable answer form; or a response that supplies its own graded counts (HIL_SUBMISSION_SELF_GRADED). Graded counts come only from `--grading`, and never exceed the number asked. The response text is hashed, never stored.

`withdraw --trials-dir <dir> --trial-id ... --withdrawn-at <ts>` records a withdrawal: the ticket can never be taken in afterwards and an existing record for it is removed.

Keep the trials directory under the owner's custody, outside this repository. `summarize --trials <dir>/records --tickets <dir>/tickets` aggregates the records. It fails closed when synthetic and actual records are mixed (HIL_SUMMARY_MIXES_SYNTHETIC_AND_ACTUAL), when a trial id repeats (HIL_SUMMARY_DUPLICATE_TRIAL_ID), when actual records come without tickets (HIL_SUMMARY_TICKETS_REQUIRED_FOR_ACTUAL_OBSERVATIONS), and when an actual record is not the one its RECORDED ticket names by digest, which catches copied, edited and withdrawn records (HIL_SUMMARY_RECORD_NOT_BOUND_TO_TICKET). For LLM cells it reports the number of models and `cross_model_variance`: the population variance across models of each model's mean interpretation accuracy, or NOT_MEASURED with fewer than two models. Model identities stay in the records, not the summary; `data/hil-explanation-experiment/results.json` is replaced only by that summary, by the owner, after real trials.

**Single path to an actual observation.** An ACTUAL_OBSERVATION record exists only through `issue` then `intake`. The shared record builder refuses an actual observation unless it receives the issued ticket it answers, in state ISSUED, for the same trial, subject, dimension, condition and packet digest, and it re-checks the recorded opt-in or provider-use permission. `validate_trial` and the trial-record schema bind the evidence locator to the evidence class: a SYNTHETIC_TEST record carries a `synthetic://` locator, and an ACTUAL_OBSERVATION record carries a non-synthetic locator naming a sha256 digest. `validate_trial` also requires that digest to be the record's response digest. A record produced any other way therefore cannot pass as an actual observation (#3106 comments 6113728583 and 6113736702).

### Hypothesis evaluation (descriptive)

`scripts/hil_explanation_experiment.py evaluate --trials <dir>/records [--tickets <dir>/tickets] [--min-trials-per-cell N]` compares condition C against condition A for every metric H1 and H2 name, and assesses H3. It accepts exactly what `summarize` accepts, so mixed evidence classes, repeated trial ids and actual observations without their recorded ticket fail closed.

The comparison is descriptive: each metric reports the A and C means, the trial counts and whether C differs in the predicted direction. No significance test is run, and no verdict says "supported". A hypothesis is NOT_MEASURED while a cell is empty and INSUFFICIENT_TRIALS while a cell has fewer than the minimum trials (10, confirmed by the owner on 2026-10-12, as is the descriptive-only analysis). Otherwise it is DIRECTIONALLY_CONSISTENT when every metric moves as predicted, DIRECTIONALLY_INCONSISTENT when any moves against, and MIXED otherwise. For H3, any holdout recognition in a fresh, unexposed session is UNDETERMINED, as preregistered. Synthetic runs report MEASURED_SYNTHETIC and are never results.

Third, actual observations were restricted to ticketed intake and the locator was bound to the evidence class (#3106 comments 6113728583 and 6113736702).
