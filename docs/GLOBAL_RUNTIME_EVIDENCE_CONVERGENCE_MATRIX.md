## Primary shared choke points

### Choke point A — authentic resident request consumption

This is the earliest missing predicate for CryptoBot and several source-complete bridge tasks. It is also a prerequisite pattern repeated across Runtime Profile Map, GLM, SV-011, GADI, and other resident-request children.

**Remediation:** promote one reusable exact-task request-consumption path through the existing resident dispatcher, with subject-bound `task_id + request_id + COSV` evidence, then project that mechanism to eligible sibling requests without claiming their execution until each exact request is consumed.

### Choke point B — subject-bound resident process observation

StegClaw, SV002, DEVICE_KV, Endpoint Fanout, StegVerse-001, and Ecosystem Chat have historically shared `resident_process_alive_supervised` as a first unresolved runtime-presence predicate.

**Remediation:** one authentic resident process observation can supply shared substrate evidence only after runtime-root / node / worker identity is bound. It does not itself prove task consumption or component execution.

### Choke point C — post-execution evidence chain

HIL, VACC, DE-006, SDK/Hugging Face and some StegVerse-001 continuations have progressed beyond generic startup and are instead missing later stages such as exact parent binding, custody/reconstruction, public projection, or propagation.

**Remediation:** treat these as later-stage lanes and reuse their proven earlier mechanisms. Do not send them back through generic runtime bootstrap unless a freshness predicate genuinely requires it.
