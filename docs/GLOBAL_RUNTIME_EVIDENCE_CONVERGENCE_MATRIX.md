## Finding

The StegBrowser milestone exposed a reusable runtime-state pattern that applies across the runtime-open ecosystem:

```text
retained StegOS node identity + continuity
+ HB32 synchronization / freshness observation
+ exact task / subject binding
+ bounded or ephemeral execution session
-> task-specific execution path
-> exact receipt / custody / reconstruction
```

The **node survives** a bounded execution-session teardown. Session-local cookies, credentials, provider sessions, navigation state, and temporary execution state do not. HeartBeat remains observation/timing/freshness/correlation only; it does not create task admission, execution permission, credentials, claims/fences, transitions, or completion.

This does **not** mean all 18 lanes are now authentically executing. It means the prior generic `UNWIRED_CHILD_RUNTIME / NO_REGISTERED_SELECTOR` category is eliminated by giving every lane one explicit HB32-synchronized StegOS runtime-node profile. Every lane can now report its actual first missing subject-bound runtime predicate instead of collapsing into a missing-selector placeholder.

Canonical source:

```text

scripts/build_runtime_profile_map.py
scripts/run_global_runtime_node_profile_convergence.py
control/runtime-observability-consumers/stegbrowser-ephemeral-runtime-binding-001.json
```

## Remaining runtime problem classes

The remaining failures should now be diagnosed as actual state, not routing absence:

1. **resident not materially present/current** — materialize/observe the task's retained node/process on the actual execution substrate;
2. **request not consumed** — use the existing exact task/COSV request path and require consumption evidence;
3. **claim/fence or InTr stage missing** — retain the same node and continue from that exact missing transition stage;
4. **provider/model/runtime dependency not materially present** — bind the external runtime to the same profile rather than creating a parallel scheduler/runtime;
5. **post-execution parent/custody/reconstruction missing** — retain prior authentic execution evidence and continue from exact parent/custody stage;
6. **physical current-device proof missing** — source/CI/profile state remains insufficient until actual device observation exists.
